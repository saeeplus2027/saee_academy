ما الذي تضيفه؟
1) رابط «مكتبة الأسئلة» في شريط التنقل بجانب الرئيسية والتخصصات والمواد وكيف تعمل المنصة.
2) صفحة مستقلة questions.html لا تعرض إلا المواد التي أضيفت لها ملفات أسئلة فعلياً.
3) عند فتح المادة تظهر كل الملفات بعناوينها التي تكتبها من لوحة الأدمن، ولكل ملف زران:
   - فتح: يفتح الملف في تبويب جديد (PDF يعرض داخل المتصفح إذا كان المتصفح يدعم ذلك).
   - تحميل: ينزّل الملف على الجهاز.
4) تبويب «مكتبة الأسئلة» في لوحة الأدمن. تختار التخصص، ثم المادة، ثم عنوان الملف وترفع PDF أو DOC أو DOCX.
5) يمكن إضافة أكثر من ملف للمادة نفسها، وحذف الملفات من لوحة الأدمن.

طريقة التركيب الآمنة:
1) نزّل آخر نسخة من مستودع GitHub main واحتفظ بنسخة احتياطية منها.
2) فك هذه الحزمة داخل جذر المستودع نفسه، واسمح باستبدال مجلد public بالنسخة الموجودة في الحزمة؛ مجلد public هنا مأخوذ من آخر نشر GitHub Pages الناجح ثم أضيفت إليه المكتبة.
3) شغّل apply_question_library_backend.bat من جذر المشروع. يجب أن يكون Python متاحاً وأن يكون الملف src/entry.py موجوداً.
4) راجع التغييرات، ثم نفّذ Commit وPush إلى main.
5) راقب GitHub Actions: نشر Pages للواجهة ونشر Cloudflare Worker بسبب تغيير src/entry.py.

قاعدة البيانات والتخزين:
- لا تنشئ D1 جديدة ولا تغيّر database_id أو bucket.
- لا تحتاج هذه الإضافة إلى Migration يدوي؛ ينشئ Worker جدول question_files عند أول استخدام.
- الملفات تُحفظ في R2 الحالي عبر binding MEDIA، ولا يُفتح bucket للعامة.
- كل API تنزيل/فتح يتطلب جلسة مستخدم مسجّل الدخول، وإضافة/حذف الملفات تتطلب صلاحية admin.
- حد الملف 50 MB، والأنواع المسموحة PDF وDOC وDOCX.

مهم:
- مكتبة الأسئلة متاحة للمستخدم الذي سجّل دخوله. وهي مستقلة عن اشتراك مشاهدة فيديوهات المادة.
- لا تشغّل ملف backend patcher من داخل مجلد public؛ شغّله من جذر المشروع.
- إذا رفض الملف التعديل لأن بنية src/entry.py تغيّرت، أوقف التنفيذ وأرسل الخطأ بدلاً من الاستبدال اليدوي العشوائي.
